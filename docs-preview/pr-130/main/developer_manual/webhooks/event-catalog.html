LibreSign event catalog

This is the native webhook catalog, listing only PHP events implemented by LibreSign with OCP\EventDispatcher\IWebhookCompatibleEvent. It is not a list of hypothetical events, and it is not a list of subscriptions already registered on a particular Nextcloud server.

Version and publication status

  • SigningRequestCompletedEvent exists on the LibreSign development branch (main, Nextcloud 36).

  • The other five entries below are implemented in unmerged draft PR `LibreSign/libresign#9427 <https://github.com/LibreSign/libresign/pull/9427>`_. They are not available on an unmodified installation of main until that PR is integrated and deployed.

  • No entry here announces a stable LibreSign 16 release. LibreSign 13, 14 and 15 do not expose these aggregate development webhooks.

The source audited for the new entries is commit 75a368c8be367dc58b1e2d4e500f3a5b4523f49c. Always check the installed revision, not just the Nextcloud version.

Available event classes

Use the full namespace OCA\Libresign\Events plus the class name shown below in the native Webhook Listeners subscription.

Implemented native contracts

Event class

Implemented in

Emitted when

SigningRequestCompletedEvent

Development main

Document or parent envelope reaches aggregate SIGNED. The workflow can contain rejected signers if policy permits completion.

SigningRequestReadyEvent

PR #9427

A newly created ready request is persisted, or a root document/envelope transitions from DRAFT to ABLE_TO_SIGN. Not on repeated status updates.

SigningRequestCanceledEvent

PR #9427

A rejection causes the root document/envelope workflow to transition to CANCELED. This is not the internal signer-removal cancellation notification.

SignerSignedWebhookEvent

PR #9427

A document-level signer action has been persisted as signed. An envelope action can produce one event per signed document, all correlated to the same parent requestUuid.

SignerRejectedWebhookEvent

PR #9427

One signer rejection has been committed, independently of the number of identification methods. It includes whether the workflow was canceled.

NotificationDeliveryStatusChangedEvent

PR #9427

A notification transport submission attempt has reached a persisted outcome in the delivery ledger. This does not prove arrival, reading or recipient receipt.

Public payloads

All six events use contractVersion: 1, a deterministic eventId for receiver-side deduplication, requestUuid of the workflow and requestType equal to document or envelope. Every receiver should authenticate, deduplicate and reconcile the current state through authorized OCS/API credentials.

Additional payload fields

Event

Fields in event

SigningRequestCompletedEvent

status: "completed"; eventId: "libresign.workflow.completed.v1:<requestUuid>".

SigningRequestReadyEvent

status: "ready_to_sign"; eventId: "libresign.workflow.ready.v1:<requestUuid>".

SigningRequestCanceledEvent

status: "canceled"; eventId: "libresign.workflow.canceled.v1:<requestUuid>".

SignerSignedWebhookEvent

status: "signed", documentUuid, signerId. eventId begins with libresign.signer.signed.v1: followed by a deterministic SHA-256 digest.

SignerRejectedWebhookEvent

status: "rejected", documentUuid, signerId, workflowCanceled (boolean). eventId starts with libresign.signer.rejected.v1: and a SHA-256 digest.

NotificationDeliveryStatusChangedEvent

deliveryId, channel, state, attempt; event ID starts with libresign.notification.delivery.v1: and includes the delivery ID, attempt and state.

The notification event’s state is the persisted result of the provider adapter: accepted, temporary_failure, permanent_failure, failed or unknown. The accepted state does not mean the recipient received the message. Retried attempts can produce new event IDs. pending and sending are not exposed as terminal submission outcomes.

Signer events deliberately expose only the non-secret numeric signerId, not a signing invitation URL, bearer-like signer UUID, email, phone number, private rejection comment, certificate or PDF data. The document UUID is a correlation identifier; file retrieval still requires separate authorization.

Subscribing and retrieving the result

An administrator installs Webhook Listeners and subscribes to an available full class name. Configure a receiver with authentication and functional Cron background jobs. For detailed configuration and the real external signing process, see Configure webhook deliveries and External signing with native webhooks.

For example, the existing completion event is registered as:

OCA\Libresign\Events\SigningRequestCompletedEvent

The Webhook Listeners application transmits the event in its native JSON wrapper; the event alone never contains the signed PDF. After validating an incoming message, the integrator must confirm ownership and retrieve the final document through authenticated LibreSign OCS and authorized Nextcloud WebDAV access.

occ webhook_listeners:list shows configured subscriptions but is not a full list of every PHP event made available by installed applications.

Testing and compatibility

The existing completion webhook has been verified in an isolated Nextcloud 36 runtime through external browser signing, authenticated HTTP POST delivery by the Nextcloud worker, and authorized retrieval of the signed PDF. The five events implemented in PR #9427 have passing focused PHP contract and service tests; their individual real HTTP delivery scenarios have not yet been homologated. Do not assume the documentation’s inclusion means those events are already installed on a production server.

Existing internal LibreSign events such as SignedEvent, SignatureRejectedEvent, SignRequestCanceledEvent and SendSignNotificationEvent are not public webhook-compatible events. Do not subscribe to them by name.
